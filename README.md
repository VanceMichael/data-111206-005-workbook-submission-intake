# 企业申报工作簿接收器

校验 OOXML 容器、列出工作表关系，并对企业表/费用表/申报表做**结构化可信采集**：沿公式依赖重算而不是读取缓存值，按企业编号关联，隔离问题申报，保留每批次证据。所有处理只用 Python 标准库，不执行宏、不刷新外链、不启动 Office。

## 运行

在 Python 3.11 或更新版本的 Linux 环境使用。原文与证据保存在 `output/raw.sqlite3`，删除 `output/` 可回到干净状态。全部示例使用本地合成数据，不包含账号凭据或真实企业资料。

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q .
python3 app.py demo
python3 app.py collect fixtures/cached.xlsx fixtures/cycle.xlsx
python3 app.py batches
```

`app.py demo` 执行原有工作表清单读取路径；`collect` 对一个或多个 xlsx 做结构化采集并写入批次证据；`batches` 查询历史批次。对不可信工作簿建议用隔离模式运行：`python3 -I app.py collect <文件>`。`--output` 可指定另一份数据库。

## 采集规则

### 表定位与关联

* 工作表名称可改。企业表/费用表/申报表依次按**定义名称 → 工作簿关系文件枚举 → 业务表头（企业编号等）**定位，结果里记录每张表的定位方式与区域。
* 三张表按**企业编号文本**关联，不使用单元格行号或固定位置；行可任意排序。企业编号（如 `0007`）保留前导零与文本语义，金额一律用 `Decimal` 十进制，序列化为字符串避免浮点误差。
* 单元格区分四种形态：**空单元格（缺失）、空字符串、错误值（#DIV/0! 等）、零**，外加普通数值/文本/布尔。

### 日期制

* 读取工作簿 `date1904` 标记，按对应 epoch 转换：1900 系统以 1899-12-31 为零点，1904 系统以 1904-01-01 为零点。
* 1900 系统的序列 60 是 Excel 兼容 1900 年虚构闰日的占位，**不伪造为真实日期**，对应申报按 `虚构闰日` 拒收；同一序列在 1904 系统是合法的 1904-03-01。

### 公式与依赖

* 支持范围：四则运算（含括号、正负号）、同簿单元格引用（含 `$` 绝对引用与表名前缀）、`SUM`、定义名称/命名区域。区域引用只允许出现在 `SUM` 内。
* 其他函数、乘方/百分比等运算符、共享/数组公式、外部工作簿引用一律标记为不支持并隔离申报。
* 先构建公式依赖图，三色 DFS 检测循环；按行的企业归属检测**跨企业引用**。问题只隔离受影响企业的受影响字段，同簿无关企业照常采集。
* 公式值全部现场重算。`<v>` 缓存仅在与重算值一致时标记为“一致”，不一致时标记“不一致”并给出旧缓存与新值，缺失缓存则现场重算。calcChain 或“自动计算”标记不参与证明，引擎本身不读取它们。

### 批次与证据

* 每次 `collect` 生成批次（按来源 + 字节 SHA-256 决定批次号）。同一文件重复导入复用原批次并刷新观察时间，可通过 `batches` 与 `EvidenceStore.evidence_for` 溯源。
* 任一依赖变化导致字节摘要不同，即产生新批次与新证据行（例如费用明细改动后，申报合计的重算值随之变化）。
* 每家企业输出可信字段、公式来源（公式文本、依赖单元格及其归属企业、重算值、缓存核对）、拒收原因代码与非阻断问题提示，并附费用表独立合计复核。

## 模块与数据

* `workbook_parser.py`：只读 OOXML 模型（容器安全校验、共享字符串、定义名称、关系、日期制、宏部件检测）。
* `formula_engine.py`：受限公式词法/语法分析、依赖收集与十进制重算。
* `dates.py`：1900/1904 日期制转换与虚构闰日拦截。
* `collector.py`：表定位、企业关联、依赖图核对、隔离决策与结构化结果。
* `evidence_store.py` / `raw_store.py`：批次证据库与原文库（SQLite 事务）。
* `make_workbooks.py` 生成含旧缓存、循环、外链、1904 日期制、空值四态、跨企业引用和改名工作表的合成文件；重新生成时原有四个文件字节不变。
